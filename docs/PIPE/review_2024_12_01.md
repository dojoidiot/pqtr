## Issues Identified

### 1. Feature Gap: No Luminance-Dependent Color Measurement

**Problem**: We measure global color (μ_a, μ_b) but NOT color at different luminance levels.

**Impact**: Split tone dials (shadow_temp, highlight_temp) have **no optimization signal**. The optimizer can't tell if shadow colors or highlight colors match the target.

**Evidence**: DSC00144 diff shows:
- Shadows → too cyan (need warmth)
- Highlights → too pink (need neutral)

This is exactly what split tone fixes, but the optimizer can't find the values because we don't measure it.

**Missing features**:
- `a_shadow`, `b_shadow` - mean a*/b* where L < L_p25
- `a_highlight`, `b_highlight` - mean a*/b* where L > L_p75

### 2. Base Curve vs Split Tone Overlap

**Current flow**:
1. Per-channel base curve applies **global** color shift
2. WB dials (temperature, tint) also apply **global** color shift
3. Split tone dials apply **luminance-dependent** color shift

**Conflict**: The per-channel base curve captures an average color shift but can't handle luminance-dependent shifts. This leaves residual error that only split tone can fix - but we don't measure it.

**Question**: Should base curve be:
- **(A) Luminance-only** - handles contrast, leaves ALL color to dials
- **(B) Per-channel RGB** - handles average color, leaves split-tone to dials

Current implementation is (B), but we're not measuring what (B) leaves behind.

### 3. Potential Redundancy

| Transform | BaseCurve (RGB) | WB Dials | Split Tone |
|-----------|-----------------|----------|------------|
| Global color shift | ✓ | ✓ | ✗ |
| Luminance contrast | ✓ | ✗ | ✗ |
| Shadow color | ✗ | ✗ | ✓ |
| Highlight color | ✗ | ✗ | ✓ |

The per-channel base curve and WB dials both affect global color. This could cause:
- WB dials fighting against base curve
- Optimizer confusion about which to adjust

---

## No Tail-Chasing Found

The progression has been logical:
1. Identified contrast gap → added base curve (luminance)
2. Fixed gamma-space bug → correct application
3. Identified color gap → added per-channel curves
4. Identified luminance-dependent color gap → current issue

Each step solved a real problem. The current gap (luminance-dependent color) is the natural next problem to solve.

## Recommendations (Priority Order)

### P1: Add Luminance-Dependent Color Features ✓ COMPLETED

**Effort**: Small (add 4 features to diff.hpp)

**Features added** (now in diff.hpp):
```cpp
constexpr int IDX_A_SHADOW = 19;     // mean a* where L < L_p25
constexpr int IDX_B_SHADOW = 20;     // mean b* where L < L_p25
constexpr int IDX_A_HIGHLIGHT = 21;  // mean a* where L > L_p75
constexpr int IDX_B_HIGHLIGHT = 22;  // mean b* where L > L_p75
```

**Impact**: Gives optimizer signal to use split tone dials effectively. Feature space now 23D.

**Completed changes**:
1. `diff.hpp`: Added feature indices, STYLE_DIM = 23
2. `diff.cpp`: Computes a/b means for shadow/highlight regions
3. `cnst.json`: Contains weights for all 23 features

### P2: Retrain Weights After P1

**Effort**: Medium (batch tune + analysis)

**Reason**: With new features, the relative importance of all features may shift.

### P3: Consider Simplifying Base Curve

**Effort**: Medium (code change + testing)

**Option**: Revert to luminance-only base curve, let:
- WB dials handle global color
- Split tone handle luminance-dependent color

**Benefit**: Cleaner separation of concerns. But wait until P1 is done to assess if needed.

### P4: Regional Features for Local Adjustments

**Effort**: Large

**Reason**: Selective color dials affect specific hue ranges. We could add per-region color features to guide them. Defer until P1-P3 are validated.

---

## Summary

**Current architecture is sound.** The base curve implementation works. The remaining gap is measurable and fixable.

**Root cause of DSC00144 issue**: We don't measure what split tone dials affect (luminance-dependent color).

**Fix**: Add 4 features (a/b in shadows, a/b in highlights). This gives the optimizer the signal it needs.

**No refactoring needed** - just extend the feature space.
