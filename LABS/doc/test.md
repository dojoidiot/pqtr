# Test Strategy

[back](../README.md)

## Purpose

This document defines the test strategy for PQTR:LABS. Testing validates that each component performs its intended function with mathematically verifiable results.

## Philosophy

### Synthetic Test Data

Tests use **synthetic images** with known properties rather than photographs. This approach provides:

- **Deterministic results**: Known input values produce predictable outputs
- **Mathematical verification**: Output can be verified against expected calculations
- **No subjective judgment**: "Correct" is defined by math, not perception
- **Fast execution**: Small images, quick generation
- **No external dependencies**: No sample photos to manage

### Module-Specific Images

Each module has synthetic test images designed to verify its specific behavior:

| Module | Test Image | Properties | Verification |
|--------|-----------|------------|--------------|
| Exposure | `exposure_ramp.png` | Gray ramp 0.0→1.0 | Value × 2^EV |
| Exposure | `exposure_midgray.png` | 18% gray (0.18) | 0.18 × multiplier |
| White Balance | `white_balance_patches.png` | Grays + R/G/B/Y | Channel ratios shift |
| Tone Map | `tone_map_hdr_ramp.png` | HDR ramp 0.0→4.0 | Highlight compression |
| Tone Map | `tone_map_ev_patches.png` | Patches at EV 0-4 | Luminance mapping |
| General | `colorchecker_srgb.png` | 24-patch ColorChecker | Industry reference |
| General | `gradient_shadow.png` | 1%→10% gradient | Banding detection |

### Test Data Generation

Synthetic images are generated by `gen_test_images`:

```bash
make -f Makefile.test gen-test-data
```

Images are stored in `tmp/var/test/data/` and regenerated on each test run to ensure consistency.

## Module Testing

### Test Pattern

Each module test follows this pattern:

1. **Load synthetic image** (gamma-encoded PNG)
2. **Convert to linear** (inverse gamma 2.2)
3. **Apply module** with specific dial values
4. **Print statistics** (min, max, mean per channel)
5. **Convert to gamma** (gamma 2.2)
6. **Save output** for visual inspection

### Verification Method

Tests print before/after statistics that can be verified against expected values:

```
Before exposure:
  Linear RGB: min=0.180144 max=0.180144 mean=[0.180144,0.180144,0.180144]

After exposure (dial=0.75, +2 EV, ×4):
  Exposed: min=0.720577 max=0.720577 mean=[0.720577,0.720577,0.720577]
```

**Verification**: 0.180144 × 4 = 0.720576 ✓

## Diff Testing

### Spectral Loss Tests (Color/Tone)

| Test Case | Input | Expected Result |
|-----------|-------|-----------------|
| Identical images | Same image twice | Spectral loss = 0.0 |
| Same style, different content | Two sunset photos | Low spectral loss (<0.1) |
| Different style, same content | Same photo, different grade | High spectral loss (>0.3) |
| Achromatic singularity | Pure gray image | No NaN, stable features |
| Scale invariance | 1024px vs 512px same image | Spectral loss ≈ 0.0 |
| Content invariance | Portrait vs landscape, same vibe | Low spectral loss |

### Frequency Loss Tests (Sharpness)

| Test Case | Input | Expected Result |
|-----------|-------|-----------------|
| Identical images | Same image twice | Frequency loss = 0.0 |
| Sharp vs blurred | Same image, one Gaussian blurred | Frequency loss > 0.5 |
| Same sharpness, different content | Two sharp photos | Low frequency loss |
| Noise sensitivity | Clean vs noisy | Noisy has higher Laplacian var |

### Feature Extraction Tests

| Test Case | Input | Verification |
|-----------|-------|--------------|
| SVD correctness | Known matrix | Singular values match analytical |
| LCH conversion | sRGB patches | L, C, H values match reference |
| Chroma weighting | Gray gradient | H_safe ≈ 0 throughout |
| Hypersphere projection | Random vector | ||ψ|| = 1.0 |
| Covariance calculation | Synthetic gradient | cov(L,C) matches expected |
| Laplacian variance | Known edge image | Variance matches expected |

### Visual Diff Tests

- [ ] Visual diff highlights changed regions
- [ ] Scale factor amplifies differences correctly
- [ ] Output image has correct dimensions

## Tune Testing

### Stage 1: SPSA Tests (Color/Tone - 17 dials + 17³ LUT)

| Test Case | Input | Expected Result |
|-----------|-------|-----------------|
| LUT estimation | Source + target images | 17³ LUT captures nonlinear color |
| Gradient estimation | Known loss surface | Gradient direction correct |
| Bounds handling | Parameters near 0 or 1 | Values stay in [0, 1] |
| Multi-start | 5 random starts | Best result selected |
| Convergence | Style transfer task | Spectral loss < 0.001 (0.1%) |
| Hyperparameter decay | 100 iterations | a_k and c_k decrease correctly |

### Stage 2: Edge Tests (Sharpness - 2 dials)

| Test Case | Input | Expected Result |
|-----------|-------|-----------------|
| Golden section convergence | Single dial optimization | Finds minimum in <20 evals |
| Sharp reference matching | Blurred source + sharp ref | Sharpen dials increase |
| Soft reference matching | Sharp source + soft ref | Sharpen dials decrease |
| L-only sharpening | RGB comparison | Colors unchanged, edges sharpened |

### Style Transfer Tests (Full Pipeline)

| Test Case | Input | Expected Result |
|-----------|-------|-----------------|
| Golden hour transfer | Neutral RAW + sunset reference | Warm tones, appropriate sharpness |
| High contrast transfer | Flat RAW + punchy reference | Increased contrast dial |
| Desaturated transfer | Vibrant RAW + muted reference | Lower saturation/vibrance |
| Content invariance | Different scenes, same style | Similar dial values |
| Output format | Full optimization | Valid tune.json with dials + LUT |

### Three Roles Verification

| Role | Dials | Handled By | Test |
|------|-------|------------|------|
| Color/Tone | 17 + LUT | GeoS (3D LUT + SPSA) | Spectral loss < 0.1% |
| Sharpness | 2 | Edge (golden section) | Frequency loss < 1% |
| Geometry | 6 | User | Not in style sidecars |

### Performance Tests

| Test | Target |
|------|--------|
| LUT estimation | < 2 seconds |
| SPSA stage (17 dials) | < 5 minutes |
| Edge stage (2 dials) | < 5 seconds |
| Full optimization | < 6 minutes |

```bash
ls tmp/var/test/output/
# exposure_neutral.png, exposure_dark.png, wb_warm.png, etc.
```

### Tune/Labs Integration Tests

```bash
# Build tune and labs binaries
make -f Makefile.tune all

# Fast optimization test (~10s)
make -f Makefile.tune test-fast

# Full optimization test (~60s)
make -f Makefile.tune test-full

# Apply existing tune.json to test RAW
make -f Makefile.tune test-labs

# Batch test: tune all pics, create comparison grid
make -f Makefile.tune test-batch
# Output: tmp/var/pics/<name>/{meta.json, tune.jpg, head.png, body.png, tune.json, tail.png, diff.png}
# Output: tmp/var/pics/compare.png (JPEG vs TAIL grid)
```

## Design Decisions

### Why Synthetic Images?

**Problem**: Testing with photos requires subjective judgment of "correct" output.

**Solution**: Synthetic images with mathematically defined properties:
- Gray ramp: Every pixel has known linear value
- ColorChecker: Industry-standard reference colors
- HDR patches: Known EV values for tone mapping

### Why Not Unit Tests with Assertions?

**Problem**: Image processing results have floating-point precision variations.

**Solution**: Print statistics for human verification + visual output inspection:
- Statistics show actual vs expected values
- Output images allow visual sanity check
- Both deterministic AND human-verifiable

### Color Space Handling

All tests follow this color space flow:
1. **Input**: Gamma-encoded PNG (sRGB)
2. **Processing**: Linear RGB (CV_32FC3)
3. **Output**: Gamma-encoded PNG (sRGB)

Tests apply inverse gamma before module, gamma after module, matching the real pipeline.

## Maintenance

### Adding New Module Tests

1. Create synthetic test image in `gen_test_images.cpp`
2. Create test executable `test_<module>.cpp`
3. Add to `Makefile.test` (sources, targets, rules)
4. Document test cases in this file

### Updating Test Images

If module behavior changes, update expected values in this document and verify new statistics match new expectations.
